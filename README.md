# NL_2026

Индивидуальная работа: 20 программ на 20 разных языках программирования.
Пять тем, на каждую тему по 4 программы.

## Порядок работы

Каждая задача делается в отдельной ветке. Имя ветки: `<номер темы>_task_<номер задачи>_<язык>`,
например `1_task_1_kotlin`.
Исходники лежат в папке своей темы: `<папка темы>/task_<номер>_<язык>/`.

## Тема 1. Многопоточность

Папка: `1_threads/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Параллельный подсчёт частоты слов в наборе текстовых файлов | Kotlin | `1_task_1_kotlin` |
| 2 | Сегментное решето Эратосфена на пуле потоков | Rust | `1_task_2_rust` |
| 3 | Обедающие философы на процессах | Elixir | `1_task_3_elixir` |
| 4 | Конвейер производитель-потребитель для разбора логов | Ruby | `1_task_4_ruby` |

1.1 Параллельный подсчёт частоты слов в наборе текстовых файлов (Kotlin). Список файлов делится между потоками, каждый поток строит свой словарь слов, затем словари сливаются в общий под блокировкой. В конце печатаются 10 самых частых слов и время работы для 1 и N потоков.

1.2 Сегментное решето Эратосфена на пуле потоков (Rust). Диапазон разбивается на блоки, блоки раздаются рабочим потокам через канал mpsc, каждый поток ищет простые числа в своём блоке и отправляет результат обратно. Главный поток собирает ответы и печатает количество простых чисел и последние десять из них.

1.3 Обедающие философы на процессах (Elixir). Каждый философ и каждая вилка это отдельный процесс, общение только сообщениями. Вилки берутся в фиксированном порядке, чтобы не было взаимной блокировки. Считается, сколько раз поел каждый философ, итог печатается по таймеру.

1.4 Конвейер производитель-потребитель для разбора логов (Ruby). Несколько потоков читают строки из файлов логов и кладут их в общую очередь Queue, несколько потоков-обработчиков разбирают строки и накапливают статистику в общей структуре под Mutex. В конце печатается сводный отчёт.

## Тема 2. Алгоритмические задачи

Папка: `2_algorithms/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Решение судоку 9x9 перебором с возвратом (рекурсия) | Haskell | `2_task_1_haskell` |
| 2 | Символьное дифференцирование выражений (рекурсия) | Scheme | `2_task_2_scheme` |
| 3 | Расстояние Левенштейна с восстановлением цепочки правок | Zig | `2_task_3_zig` |
| 4 | Кратчайший путь в графе алгоритмом Дейкстры | Scala | `2_task_4_scala` |

2.1 Решение судоку 9x9 перебором с возвратом (Haskell). Поле читается из строки из 81 символа. Рекурсивная функция ставит цифру в первую пустую клетку, проверяет строку, столбец и квадрат 3x3 и идёт дальше, при неудаче откатывается. Печатается решённое поле и число просмотренных вариантов.

2.2 Символьное дифференцирование выражений (Scheme). Выражение задаётся списком, например (+ (* 3 (^ x 2)) (* 2 x)). Программа рекурсивно обходит дерево выражения, применяет правила дифференцирования и упрощает результат: убирает умножение на 1 и 0, сворачивает числовые константы.

2.3 Расстояние Левенштейна с восстановлением цепочки правок (Zig). Строится матрица динамического программирования, считается минимальное число вставок, удалений и замен. Затем обратным проходом по матрице восстанавливается сама последовательность операций и печатается по шагам.

2.4 Кратчайший путь в графе алгоритмом Дейкстры (Scala). Граф читается из файла со списком рёбер. Приоритетная очередь написана вручную, это бинарная куча на массиве, готовые коллекции с приоритетом не используются. Выводится длина пути и сам путь от начальной вершины до конечной.

## Тема 3. Ввод/вывод в консоль и файл

Папка: `3_io/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Разбор лог-файла веб-сервера и отчёт в файл | Perl | `3_task_1_perl` |
| 2 | Консольный менеджер задач с хранением в файле | Lua | `3_task_2_lua` |
| 3 | Hex-дамп файла и обратная сборка файла из дампа | Nim | `3_task_3_nim` |
| 4 | Разрезание файла на части и обратная сборка | D | `3_task_4_d` |

3.1 Разбор лог-файла веб-сервера и отчёт в файл (Perl). Файл лога читается построчно, из строк вытаскиваются IP, дата, код ответа и размер ответа. С консоли запрашивается фильтр (например, только коды 4xx и 5xx). Статистика по IP, кодам и трафику выводится на экран и записывается в отдельный файл отчёта.

3.2 Консольный менеджер задач с хранением в файле (Lua). В цикле читаются команды: add, list, done, del, find, exit. Список задач хранится в текстовом файле, при запуске он читается, после каждого изменения перезаписывается. Есть проверка неверного ввода и вывод в виде таблицы.

3.3 Hex-дамп файла и обратная сборка файла из дампа (Nim). Программа читает файл побайтово и печатает дамп в привычном виде: смещение, 16 байт в шестнадцатеричном виде, справа печатные символы. Дамп сохраняется в текстовый файл. Обратный режим собирает из дампа исходный файл и сравнивает его с оригиналом.

3.4 Разрезание файла на части и обратная сборка (D). Файл режется на куски заданного размера, для каждого куска считается контрольная сумма и пишется файл описания. Второй режим собирает файл обратно из кусков, проверяет контрольные суммы и сообщает, если часть повреждена или потеряна.

## Тема 4. Клиент-серверное взаимодействие

Папка: `4_client_server/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | TCP-чат на несколько клиентов | Erlang | `4_task_1_erlang` |
| 2 | Сетевое хранилище ключ-значение | Julia | `4_task_2_julia` |
| 3 | Игра «угадай число» по сети | OCaml | `4_task_3_ocaml` |
| 4 | Мини HTTP-сервер на сокетах | Groovy | `4_task_4_groovy` |

4.1 TCP-чат на несколько клиентов (Erlang). Сервер на gen_tcp принимает подключения, на каждого клиента запускается свой процесс, список клиентов держит отдельный процесс-диспетчер. Сообщение от одного клиента рассылается всем остальным. Поддерживаются ник при входе и команда выхода.

4.2 Сетевое хранилище ключ-значение (Julia). Сервер держит словарь в памяти и понимает текстовые команды SET, GET, DEL, KEYS, QUIT. Каждый клиент обслуживается в своей задаче, доступ к словарю защищён блокировкой. Клиент отправляет команды с консоли и печатает ответы сервера.

4.3 Игра «угадай число» по сети (OCaml). Сервер на сокетах из модуля Unix загадывает число для каждого подключившегося клиента и отвечает «больше», «меньше» или «угадал», считая попытки. Для каждого клиента создаётся отдельный процесс. Клиент вводит числа с консоли.

4.4 Мини HTTP-сервер на сокетах (Groovy). Сервер поднят на ServerSocket и сам разбирает строку запроса и заголовки, без готовых веб-фреймворков. Отдаёт файлы из каталога с нужным Content-Type, на адрес /stats возвращает счётчики запросов, на неизвестный путь отвечает 404. Клиент шлёт запросы и печатает ответ.

## Тема 5. Конвертация данных из одного формата в другой

Папка: `5_convert/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | CSV в JSON | Swift | `5_task_1_swift` |
| 2 | JSON в XML | F# | `5_task_2_fsharp` |
| 3 | Markdown в HTML | Clojure | `5_task_3_clojure` |
| 4 | XML в CSV | Lisp | `5_task_4_lisp` |

5.1 CSV в JSON (Swift). Свой разборщик CSV: понимает кавычки, запятые и переводы строк внутри полей, удвоенные кавычки. Первая строка считается заголовком. На выходе массив объектов JSON с правильным экранированием и отступами.

5.2 JSON в XML (F#). Рекурсивный разборщик JSON собирает дерево из объектов, массивов, строк, чисел и литералов true/false/null, а затем печатает его как XML с отступами. Элементы массива получают одинаковые теги с атрибутом индекса, спецсимволы экранируются.

5.3 Markdown в HTML (Clojure). Поддерживается подмножество разметки: заголовки, маркированные и нумерованные списки, жирный и курсив, инлайн-код и блоки кода, ссылки, цитаты и абзацы. На выходе получается готовая HTML-страница с заголовком и минимальными стилями.

5.4 XML в CSV (Lisp). Разбирается простой XML с однотипными записями, теги превращаются в списки. Программа собирает полный набор имён полей по всем записям и выгружает таблицу в CSV, экранируя запятые и кавычки. Пропущенные поля заполняются пустыми значениями.
